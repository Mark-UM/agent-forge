# Archived Proposal: V2.5 — 自进化闭环执行规划

> Speculative historical proposal. No implementation status is implied.

> **版本**：v2.5.0
> **阶段类型**：智能跃迁（Intelligence Leap）
> **预计周期**：3-4 月
> **前置条件**：v2.0 验收通过（Multi-Agent + autonomous loop + SWE-bench Verified 30%+）
> **核心目标**：从被动记录进化为主动学习，实现"越用越聪明"，用户修正率下降 30%+
> **核心策略**：DSPy 自动提示词优化 + 模式抽取 + 失败学习 + 主动学习

---

## 1. 背景与必要性

### 1.1 为何需要 v2.5

v2.0 后项目自主性达到 L4.5，但**自我改进仍是被动记录**（落后 Cursor / Devin）。

四大差距（来自全球 SOTA 对标）：
1. **无自动模式抽取**：A/B 数据采集了但没人用
2. **无失败学习**：相同错误重复犯
3. **无自适应提示词**：prompt 静态，不会根据任务自动调整
4. **无主动学习**：不主动询问用户偏好

v2.5 通过**自进化闭环**解决这四个差距，真正实现"越用越聪明"。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| 数据驱动 | 所有自进化基于交互数据，非臆测 |
| 人审机制 | 关键 patterns 需用户确认 |
| 可回滚 | 任何自进化调整可回滚 |
| A/B 验证 | 自进化效果需 A/B 测试验证 |
| 隐私优先 | PII 双重脱敏 |

#### P0-2: 模式抽取（Pattern Extraction）

**问题**：v1.5 A/B 数据采集了但没人用，不会自动学习。

**方案**：
- 新增 `modules/learning/pattern_extractor.py`：
  - 每周/每月定时运行
  - 从 interactions 抽取成功模式
  - 输出 `patterns.json`

- 抽取维度：

| 维度 | 模式示例 |
|------|---------|
| 任务类型识别 | "修复 bug" → 优先 Planner+Coder+Tester |
| 工具选择 | Python 文件 → read + edit，不用 write |
| Agent 协作 | 多文件修改 → Coder+Tester 并行 |
| 提示词效果 | terse mode + coding → Score 8.7 |
| 错误模式 | "fail to compile" → 自动检查依赖 |
| 时长模式 | bug_fix 平均 180s，feature 平均 600s |
| 用户修正模式 | 用户常修正 naming → 加强 naming context |

- 抽取算法：
  - 简单统计（mean / median / mode）
  - 关联规则（apriori）
  - 决策树（scikit-learn，可选）

**开源工具**：
- scikit-learn（BSD，轻量模式抽取）
- pandas（BSD，数据分析）

**影响文件**：
- `modules/learning/pattern_extractor.py`（新增）
- `modules/learning/tests/test_pattern_extractor.py`（新增）
- `.opencode/commands/learn.md`（新增 slash 命令，手动触发抽取）

**验收**：
- 抽取 ≥ 30 个 patterns（500+ interactions 后）
- patterns 准确率 ≥ 70%（人工评估）

#### P0-3: 自适应提示词（DSPy 集成）

**问题**：v1.5 prompt 是静态的，不会根据任务自动调整。SOTA（Cursor）已开始根据隐式反馈调整。

**方案**：
- 引入 DSPy（MIT，Stanford）自动提示词优化
- 新增 `modules/learning/adaptive_prompt.py`：
  - 基于 patterns.json 自动调整 prompt 组合
  - 示例：发现 "Python 重构 + socratic mode" Score 9.1 → 自动应用
  - A/B 验证调整效果

- 自适应策略：

```python
def adaptive_compose(task_type, file_context, history):
    patterns = load_patterns()
    # 查找匹配模式
    matched = find_matching_patterns(patterns, task_type, file_context)
    if matched and matched.confidence > 0.8:
        # 应用模式推荐的 profile / contexts / examples
        return compose(
            profile=matched.recommended_profile,
            contexts=matched.recommended_contexts,
            examples=matched.recommended_examples,
        )
    else:
        # fallback 到默认 compose
        return compose()
```

- DSPy 用于：
  - 自动优化 task prompt 措辞
  - 自动选择 best few-shot examples
  - 自动调整 profile 推荐

**开源工具**：
- DSPy（MIT，自动提示词优化）

**影响文件**：
- `modules/learning/adaptive_prompt.py`（新增）
- `modules/prompt/composer.py`（修改，集成 adaptive_compose）
- `modules/learning/tests/test_adaptive_prompt.py`（新增）
- `requirements-learning.txt`（新增）

**验收**：
- 自适应提示词覆盖率 ≥ 60%（500+ interactions 后）
- 相同类型任务平均 Score 提升 ≥ 0.5
- A/B 测试显著性 p < 0.05
- 测试 ≥ 15 个

#### P0-4: 失败学习（Failure Learning）

**问题**：相同错误重复犯，无失败案例库。

**方案**：
- 新增 `modules/learning/failure_learner.py`：
  - 自动收集失败案例（Score < 7 或 user_satisfied = False）
  - LLM 分析根因
  - 生成 lessons_learned.md
  - 自动更新 prompt（如增加 checklist）

- 失败案例库结构：

```
_runtime/learning/failures/
├── 2026-10/
│   ├── 20261001_001_failure.md
│   ├── 20261001_002_failure.md
│   └── ...
├── 2026-11/
│   └── ...
└── lessons_learned.md  # 总结的教训
```

- 失败案例格式：

```markdown
# Failure Case 001 — 2026-10-01

## Task
修复 auth.py 的 SQL 注入漏洞

## What Went Wrong
Agent 使用了字符串拼接修复，引入了新的注入点

## Root Cause (LLM 分析)
- AGENTS.md 未强调 SQLAlchemy 参数化查询
- 缺少 SQL 安全审查 checklist

## Lesson Learned
- 在 prompts/tasks/security.md 中加入 SQL 注入 checklist
- review-risk agent 应增加 SQL 注入专项检查

## Action Taken (自动)
- 已更新 prompts/tasks/security.md
- 已更新 .opencode/agents/review-risk.md

## Status
- [x] 自动修复
- [ ] 人审确认
```

- 人审机制：自动修复后需用户确认（避免学到错误模式）

**开源工具**：
- 无（自研 + DeepSeek Flash 根因分析）

**影响文件**：
- `modules/learning/failure_learner.py`（新增）
- `modules/learning/tests/test_failure_learner.py`（新增）
- `.opencode/prompts/tasks/security.md`（自动更新示例）

**验收**：
- 失败案例 100% 收集
- LLM 根因分析准确率 ≥ 60%
- lessons_learned.md 自动生成
- 用户修正率下降 ≥ 30%
- 测试 ≥ 15 个

## 5. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 自进化学到错误模式 | 中 | 高 | 人审机制 + A/B 验证 + 回滚 |

| 模式抽取数据不足 | 高 | 中 | 冷启动：用 v1.5-v2.0 历史数据 |
| 主动学习打扰用户 | 中 | 中 | 频率限制 ≤ 1 次/天 |
| LLM 根因分析准确率低 | 中 | 中 | 人审兜底 + 多模型投票 |
| 知识图谱复杂度过高 | 低 | 中 | 先用简单 JSON，必要时再 neo4j |
