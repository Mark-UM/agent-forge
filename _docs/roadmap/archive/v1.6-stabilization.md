# Archived Plan: V1.6 — 巩固与漏洞修复执行规划

> Historical plan. Not a current specification or status report.

> **版本**：v1.6.0
> **阶段类型**：稳定化（Stabilization）
> **预计周期**：1-2 周
> **前置条件**：v1.5 验收通过（已完成，171 测试 0 遗留 Bug）
> **核心目标**：修复 v1.5 所有已知遗留，文档与代码 100% 对齐，review hook 强制化
> **不涉及**：任何新功能性升级（功能性升级归 v1.7）

## 1. 背景与必要性

### 1.1 为何需要 v1.6

v1.5 验收虽然通过，但三轮审核累计发现 12 项 Bug（已修复）+ 8 项已知遗留（L1-L8）。其中：
- **L1-L4** 是文档/数据一致性问题，影响信任度
- **L5-L6** 是工程化不足（并发安全 + hook 强制性），影响后续 v2.0 多 Agent 扩展
- **L7-L8** 是 v1.7/v2.5 才解决的问题，本版本暂不处理

**v1.6 的核心价值**：在 v1.7 引入开源工具、v2.0 引入 Multi-Agent 之前，**先把基础打牢**，避免在脆弱的基础上叠加新功能。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| 不引入新功能 | 仅修复漏洞与对齐文档 |
| 不引入新依赖 | 仅使用 Python stdlib + 已有依赖 |
| 每个修复附回归测试 | 防止复发 |
| 文档与代码同步 | 修改代码必同步文档 |
| 三轮审核机制 | 沿用 v1.5 的审核流程 |

## 2. 任务清单

### 2.1 P0 任务（必须完成）

#### P0-1: experiments.py UUID 实验 ID

**问题**：`experiments.py` L66 使用 `exp-{int(datetime.now().timestamp())}` 生成实验 ID，粒度为秒，同秒实验 ID 冲突。v2.0 多 agent 并发时冲突概率显著上升。

**修复方案**：
- 使用 `uuid.uuid4().hex[:12]` 替代秒级 timestamp
- 保留 `timestamp` 字段记录时间
- 格式：`exp-{uuid12}`（如 `exp-a3f5b2c1d4e6`）
- 向后兼容：读取旧 `exp-{timestamp}` 格式仍正常工作

**影响文件**：
- `modules/prompt/experiments.py`
- `modules/prompt/tests/test_experiments.py`（新增回归测试）

**验收**：
- 同秒生成 100 个实验，ID 全部唯一
- 旧 experiments.jsonl 仍可正常读取与统计
- 新增 ≥ 2 个回归测试

---

#### P0-2: review hook 强制化（plugin 化）

**问题**：`.opencode/commands/review.md` 中的 Post-Review Hook 是 Markdown 指导文档，依赖 Agent 自觉执行。实测发现 Agent 偶尔会跳过 hook，导致 experiments.jsonl 数据缺失。

**修复方案**：
- 新建 `.opencode/plugins/review-hook/` TypeScript plugin
- 在 review 命令完成后自动触发，不依赖 Agent
- plugin 逻辑：
  1. 解析 review 输出的 Score
  2. 统计 critical/major/minor findings
  3. 调用 `python -m modules.prompt.experiments --log ...`
  4. 失败时记录到 `_runtime/prompt/hook_errors.log`

**影响文件**：
- `.opencode/plugins/review-hook/index.ts`（新增）
- `.opencode/plugins/review-hook/package.json`（新增）
- `.opencode/commands/review.md`（移除 hook 指导段落，引用 plugin）
- `opencode.json`（注册 plugin）
- `modules/prompt/tests/test_review_hook_integration.py`（新增集成测试）

**验收**：
- review 完成后 100% 触发 experiments.py --log
- hook 失败有明确日志，不影响主流程
- 集成测试 ≥ 3 个（成功 / 解析失败 / experiments.py 失败）

### 2.2 P1 任务（应该完成）

#### P1-1: composer.py 直接脚本调用兼容

**问题**：`composer.py` L289 `from .log import ...` 是相对导入，仅在 `python -m modules.prompt.composer` 模式下有效。直接 `python modules/prompt/composer.py --pre-session` 会 ImportError。v1.5 R3 已文档化此限制，但未修复。

**修复方案**：
- 在 `composer.py` 末尾的 `if __name__ == "__main__":` 块前添加 shim：
  ```python
  if __name__ == "__main__" and __package__ is None:
      import sys
      from pathlib import Path
      sys.path.insert(0, str(Path(__file__).resolve().parent.parent.parent))
      __package__ = "modules.prompt"
  ```
- 同时更新 docstring，说明两种调用方式均可

**影响文件**：
- `modules/prompt/composer.py`
- `modules/prompt/tests/test_composer.py`（新增直接脚本调用测试）

**验收**：
- `python modules/prompt/composer.py --pre-session` 与 `python -m modules.prompt.composer --pre-session` 均可工作
- 新增 ≥ 1 个回归测试

  4. manifest.json 声明的文件是否全部存在

**影响文件**：

- `modules/meta/tests/test_drift_check.py`（新增）
