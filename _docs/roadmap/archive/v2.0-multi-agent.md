# Archived Proposal: V2.0 — Multi-Agent 编码集群与自主性跃迁执行规划

> Speculative historical proposal. No implementation status is implied.

> **版本**：v2.0.0
> **阶段类型**：架构跃迁（Architecture Leap）
> **预计周期**：2-3 月
> **前置条件**：v1.7 验收通过（向量检索 + Flash 路由 + Skills 60+ + SWE-bench 基线）
> **核心目标**：从单 agent 编码进化为 Planner/Coder/Reviewer/Tester 多 agent 协同，引入 autonomous loop，自主性 L4 → L4.5
> **核心策略**：CrewAI 编排 + 自研轻量通信 + SQLite 持久化

---

## 1. 背景与必要性

### 1.1 为何需要 v2.0

v1.7 后项目在 Prompt Engineering / Context / 路由 / Skills / 评估都已达到 A+ 级，但**自主性仍是 L4**（落后 Devin L5）。

三大差距（来自全球 SOTA 对标）：
1. **Multi-Agent 仅限审查**：编码仍是单 agent，复杂任务无法分解并行
2. **无 autonomous loop**：每步需用户确认，无法自主完成
3. **并发不安全**：experiments.jsonl 非原子写入，多 agent 时数据丢失

v2.0 通过**Multi-Agent 编码集群 + autonomous loop**解决前两个，**SQLite 迁移**解决第三个。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| 渐进式引入 | 先 2 agent（Planner+Coder），后 4 agent（+Reviewer+Tester） |
| 编排框架优先 | 优先 CrewAI / LangGraph，不自研调度器 |
| 最小权限 | 每 agent 独立 permission，杜绝越权 |
| 可观测 | 全链路 trace + 状态持久化 |
| 回滚能力 | Agent 崩溃 / 任务失败可回滚 |

## 2. 任务清单

### 2.1 P0 任务（必须完成）

#### P0-1: CrewAI 编排框架集成

**问题**：当前多 agent 仅限 review（3 个 subagent 串联），编码单 agent。需要引入编排框架支持复杂任务分解与并行。

**方案**：
- 引入 CrewAI 作为编排框架（MIT，11k+ stars）
- 定义 4 个 agent 角色：

| Agent | 模型 | 权限 | 职责 |
|-------|------|------|------|
| Planner | V4 Pro | read only | 任务分解 + DAG 规划 |
| Coder | V4 Pro | edit/write/bash | 编码实现 |
| Reviewer | V4 Flash | deny all | 代码审查（code/structure/risk 三合一） |
| Tester | V4 Flash | bash (test only) | 测试编写 + 运行 |

- CrewAI 负责任务分配 / 并行调度 / 结果汇总
- 与 OpenCode 的 oh-my-opencode plugin 协同

**PoC 验证（Week 1）**：
- 用 CrewAI 跑通一个简单 2 agent 场景（Planner + Coder）
- 评估 CrewAI 与 OpenCode 集成难度
- 如果 CrewAI 不合适，fallback 到 LangGraph 或自研轻量编排

**开源工具**：
- CrewAI（MIT）
- LangGraph（MIT，备选）

**影响文件**：

#### P0-2: Agent 通信协议与消息队列

**问题**：Multi-Agent 需要可靠通信机制。当前 experiments.jsonl 非原子写入，多 agent 并发会丢数据。

**方案**：
- Agent 间通信：基于文件 + fcntl/portalocker 锁
- 消息格式：

```json
{
  "msg_id": "uuid",
  "from": "planner",
  "to": "coder",
  "task_id": "task-001",
  "type": "assign|result|query|ack",
  "content": {...},
  "timestamp": "2026-08-01T10:00:00Z",
  "trace_id": "uuid"
}
```

- 目录结构：

```
_runtime/agent_messages/
├── orchestrator/
│   ├── tasks.jsonl       # 任务队列
│   └── results.jsonl     # 结果汇总
├── coder/
│   ├── inbox.jsonl
│   └── outbox.jsonl
└── ... (其他 agent)
```

- 每条消息原子写入（write + flush + fsync）
- trace_id 贯穿整个任务链路

**开源工具**：
- portalocker（MIT，跨平台文件锁）

**影响文件**：
- `modules/agent/messaging.py`（新增）
- `modules/agent/tests/test_messaging.py`（新增）

**验收**：
- 100 条消息并发写入 0 丢失
- 消息延迟 < 100ms
- 测试 ≥ 10 个

#### P0-3: Autonomous Loop（task-complete 判定器）

**问题**：当前每步需用户确认，无法自主完成。SOTA（Devin）可端到端完成 GitHub Issue。

**方案**：
- 新增 `modules/agent/autonomous_loop.py`：
  - task-complete 判定器：LLM 判断任务是否完成
  - 自动重试机制：失败时自动重试（max 3 次）
  - 关键节点确认：仅关键操作（如 PR 提交）需用户确认
  - 超时机制：单任务超时 30 分钟自动暂停

- 任务完成判定标准：
  - 所有测试通过
  - Review Score ≥ 7/10
  - 无 critical findings
  - 用户原始请求已解决（LLM 判断）

- 决策树：

```
任务执行
   ↓
测试通过？ ──No──→ 自动重试（max 3）
   │ Yes
Review Score ≥ 7？ ──No──→ 自动修复（max 2）
   │ Yes
Critical findings = 0？ ──No──→ 自动修复
   │ Yes
任务完成 → 通知用户
```

**开源工具**：
- 无（自研 + DeepSeek Flash 判定）

**影响文件**：
- `modules/agent/autonomous_loop.py`（新增）
- `modules/agent/task_complete_judge.py`（新增）
- `modules/agent/tests/test_autonomous_loop.py`（新增）
- `.opencode/commands/agent.md`（新增 slash 命令，启动 autonomous 模式）

**验收**：
- 简单任务（单文件 bug 修复）自主完成率 ≥ 60%
- 中等任务（多文件 feature）自主完成率 ≥ 30%
- 关键节点 100% 用户确认
- 测试 ≥ 15 个

#### P0-4: 并发安全 — SQLite 迁移

**问题**：L5 遗留 — experiments.jsonl 非原子写入，多 agent 并发会丢数据。

**方案**：
- experiments.jsonl 迁移到 SQLite + WAL 模式
- 复用已有 sqlite MCP
- 数据库 schema：

```sql
CREATE TABLE experiments (
    experiment_id TEXT PRIMARY KEY,
    timestamp TEXT NOT NULL,
    prompt_version TEXT,
    task_type TEXT,
    profile TEXT,
    task_description TEXT,
    contexts TEXT,  -- JSON
    examples TEXT,  -- JSON
    outcome_review_score REAL,
    outcome_review_findings_critical INTEGER,
    outcome_review_findings_major INTEGER,
    outcome_review_findings_minor INTEGER,
    outcome_duration_seconds INTEGER,
    outcome_tokens_used INTEGER,
    outcome_user_satisfied INTEGER,  -- NULL/0/1
    user_feedback TEXT
);

CREATE INDEX idx_experiments_task_type ON experiments(task_type);
CREATE INDEX idx_experiments_timestamp ON experiments(timestamp);

CREATE TABLE interactions (
    interaction_id TEXT PRIMARY KEY,
    timestamp TEXT NOT NULL,
    user_request TEXT,
    agent_decision TEXT,  -- JSON
    outcome TEXT,  -- JSON
    trace_id TEXT
);

CREATE TABLE agent_messages (
    msg_id TEXT PRIMARY KEY,
    trace_id TEXT,
    from_agent TEXT,
    to_agent TEXT,
    task_id TEXT,
    msg_type TEXT,
    content TEXT,  -- JSON
    timestamp TEXT
);
```

- 提供 JSONL 导出工具（向后兼容）
- 迁移脚本：将现有 experiments.jsonl 导入 SQLite

**开源工具**：
- SQLite（已有 MCP，Python stdlib sqlite3）

**影响文件**：
- `modules/prompt/experiments_db.py`（新增，SQLite 后端）
- `modules/prompt/experiments.py`（修改，支持双后端）
- `modules/agent/messaging.py`（修改，使用 SQLite）
- `modules/prompt/tests/test_experiments_db.py`（新增）
- `modules/prompt/migrate_jsonl_to_sqlite.py`（新增迁移脚本）

**验收**：
- 100 并发写入 0 丢失
- 读写性能不下降（< 10ms）
- 迁移脚本 100% 数据完整
- 测试 ≥ 15 个

### 2.2 P1 任务（应该完成）

#### P1-1: 任务 DAG 自动分解

**问题**：复杂任务（多文件 feature）需要自动分解为子任务 DAG。

**方案**：
- Planner agent 接收用户请求
- LLM 驱动分解为子任务
- 输出 DAG（有向无环图）：

```json
{
  "task_id": "task-001",
  "user_request": "添加用户认证模块",
  "subtasks": [
    {"id": "st-1", "agent": "coder", "deps": [], "desc": "实现 auth/login.py"},
    {"id": "st-2", "agent": "coder", "deps": [], "desc": "实现 auth/session.py"},
    {"id": "st-3", "agent": "tester", "deps": ["st-1", "st-2"], "desc": "编写测试"},
    {"id": "st-4", "agent": "reviewer", "deps": ["st-3"], "desc": "审查"}
  ]
}
```

- 调度器按 DAG 拓扑排序执行，无依赖的并行

**开源工具**：
- LangGraph（DAG 调度，备选）或 networkx（图算法）

**影响文件**：
- `modules/agent/planner.py`（新增）
- `modules/agent/dag_scheduler.py`（新增）
- `modules/agent/tests/test_planner.py`（新增）
- `modules/agent/tests/test_dag_scheduler.py`（新增）

**验收**：
- 复杂任务自动分解为 ≥ 3 子任务
- DAG 调度正确（无死锁）
- 并行任务比例 ≥ 30%
- 测试 ≥ 10 个

#### P1-2: Agent 状态持久化与崩溃恢复

**问题**：Agent 崩溃后无法恢复，需从头开始。

**方案**：
- 状态持久化到 SQLite：

```sql
CREATE TABLE agent_state (
    agent_name TEXT,
    task_id TEXT,
    state TEXT,  -- JSON: current step, progress, intermediate results
    updated_at TEXT,
    PRIMARY KEY (agent_name, task_id)
);
```

- 每个 agent 完成一步后 checkpoint
- 崩溃后从最近 checkpoint 恢复
- 超时任务可手动恢复

**影响文件**：
- `modules/agent/state.py`（新增）
- `modules/agent/agents/*.py`（修改，加 checkpoint）
- `modules/agent/tests/test_state.py`（新增）

**验收**：
- Agent 崩溃后可恢复到最后 checkpoint
- 数据丢失 < 1 步
- 测试 ≥ 10 个
