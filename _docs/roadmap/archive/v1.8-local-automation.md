## 0. 文档定位与协调声明

### 0.1 为何单独成版本

本计划源于用户提出的"操作电脑自动浏览网站 → 截屏 → 喂解码器 → AI 总结 → 写文件 → 自检索 → 入日程 → 闹钟提醒"需求。深度审计后确认：

- 现有模块（vision/browser/search/aggregator）已具备约 60% 的基础积木
- 但**编排层、调度层、提醒层**三层核心组件完全缺失
- **解决方案**：clone 高质量开源项目（browser-use 95K★ / APScheduler / apprise）替代三层自研，仅写薄适配层
- 该需求与 CODING_DISCIPLINE_UPGRADE 的"编码纪律"关注点正交，可并行推进
- 不属于 v1.6（漏洞修复）/v1.7（质量深化）/v2.0（Multi-Agent 编码）/v2.5（自进化）任一范畴
- 与 v3.5"本地应用自动化"互补：v3.5 控制操作系统级应用（pyautogui + pywin32 + WeChat/VSCode/Office adapter），v1.8 编排已有 AI 模块做信息收集与总结归纳

因此定位为独立 v1.8 版本，作为 v1.5 → v2.0 之间的并行能力扩展分支。

### 0.2 与其他版本的边界

| 版本 | 关注点 | 与 v1.8 的关系 |

### 2.4 开源项目 clone 策略（新增）

#### 2.4.1 策略原则

v1.8 作为"扩展模块"**破例** ONBOARDING §1.5 stdlib only 约束，引入高质量开源项目。原则：

1. **优先 clone 而非自研**：高质量（≥10K★ + 近 3 月活跃）+ MIT/Apache 2.0/BSD 协议的开源项目直接 clone 使用
2. **薄适配层**：开源项目通过 ~50-150 行适配层对接项目既有模块，不修改开源项目源码
3. **锁定版本**：clone 时锁定具体 commit/tag，避免上游 breaking change
4. **后期可优化**：初期优先功能可用，后期可升级版本或替换为更优方案
5. **放在 `vendor/` 目录**：clone 的开源项目放在 `vendor/` 下，与项目自有代码隔离
6. **破例范围限定**：仅 v1.8 的编排层/调度层/通知层破例，其他模块（search/vision/mcp）保持 stdlib only

#### 2.4.2 开源项目选型清单

| 项目 | 用途 | Stars | License | 版本 | 集成方式 | 替代的自研工作 |

#### B1: browser-use 适配层 `modules/orchestrator/agent_wrapper.py`

**核心设计**：封装 browser-use Agent，对接项目既有 vision/aggregator/write_file 模块。

**核心函数**：
```python
from browser_use import Agent
from modules.vision.recognize import _call_vision_api
from modules.search.aggregator import aggregate_results
from modules.search.privacy import redact_outbound

def run_collection_pipeline(
    target: str,              # URL 或查询
    output_path: str,         # 报告输出路径
    strategy: str = "auto",   # auto | browser | search
    max_steps: int = 10,
    llm_config: dict = None,  # DeepSeek 配置
) -> dict:
    """
    端到端收集管道（基于 browser-use）：
    1. 判定 strategy：URL → browser-use Agent；query → search parallel
    2. browser 路径：browser-use Agent 自主浏览+截图 → vision recognize 补充 OCR → aggregator
    3. search 路径：planner → parallel → aggregator
    4. 写文件：open(output_path, 'w').write(aggregated_markdown)
    5. 返回 {path, tokens_used, steps_taken, success}
    """
```

**browser-use 集成要点**：
- browser-use 内置 LLM 决策循环（navigate/click/extract），无需自研状态机
- 通过 `Agent(task=..., llm=..., browser=browser_config)` 初始化
- 截图由 browser-use 自动管理，vision 模块作为"复杂页面 OCR 补充"
- 失败降级：browser-use 失败 → 降级到 search parallel + fetch_mcp

**降级链**：
- browser-use Agent 失败 → 降级到 search parallel
- vision API 失败 → 降级到 browser-use 内置 extract
- aggregator 失败 → 降级到机械拼接 raw findings
- 写文件失败 → 写 `_runtime/fallback/{timestamp}.md` 并 log

**优先级**：P0

def main_loop():
    while True:
        now = datetime.now(timezone.utc)
        due_items = schedule_store.query(
            status='pending',
            due_at_lte=now + timedelta(minutes=5),
            notified_at_lt=now - timedelta(minutes=15)  # 避免重复通知

def create_notifier(config_path: str = "markconfig/apprise.yml") -> apprise.Apprise:
    """

def notify(item: dict, notifier: apprise.Apprise = None) -> bool:

### 4.4 安全设计

| 风险 | 缓解 |
|------|------|
| 日程内容含 PII（个人行程） | 写入 schedules 表前调用 `privacy.redact_outbound()` 脱敏；通知体仅显示 title，不显示 description |

## 6. 风险评估

### 6.1 技术风险

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| OpenCode 关闭时 reminder 无法唤醒用户处理待办 | 高 | 高 | D3 兜底：通知体含 start-opencode.bat 路径；未来 v2.0 走 headless 模式 |
| browser-use 与现有 browser daemon 功能重叠 | 中 | 低 | v1.8 优先用 browser-use（更强大），browser daemon 保留作为 fallback；未来 v3.5 时统一 |
| APScheduler 4.x API 变化（相比 3.x） | 中 | 低 | 锁定 4.x stable tag，适配层隔离 API 差异 |
| apprise Windows toast 渠道在 Win11 行为变化 | 低 | 低 | apprise 社区维护，多渠道兜底（Email / webhook） |
| ChromaDB 多 collection 内存占用过高 | 中 | 中 | B3 file_indexer 限制单 collection 文档数 ≤ 1000，超出走分片 |
| browser-use Agent 单任务执行（无并发） | 高 | 中 | v1.8 串行处理；未来 v2.0 多 agent 时改造为并发 |
| DeepSeek API 限流导致 aggregator 失败 | 中 | 中 | 复用 search 模块降级链：flash → snippet → raw findings |
| 开源项目停止维护 | 低 | 中 | git submodule 锁定 commit；停止维护时 fork 自维护（详见 §2.4.5） |

### 6.2 安全风险

| 风险 | 缓解 |
|------|------|
| 日程内容泄露个人行程 | PII 脱敏 + 通知体仅显示 title |
| scheduler custom job 执行任意代码 | 白名单模块限制 + 拒绝 `eval`/`exec` |
| reminder daemon 被外部访问 | 仅监听 127.0.0.1 + CORS 限定本机 |
| 报告文件包含敏感 URL/凭据 | 写入前 PII 脱敏 + 文件权限 600 |
| 开源依赖供应链攻击 | 锁定 commit/tag + requirements 哈希校验 + 定期 audit（详见 §2.4.5） |
| browser-use Agent 访问恶意网页 | browser-use 基于 Playwright 沙箱；URL scheme 白名单复用现有 browser daemon 校验 |
| apprise 配置文件含邮件/Webhook 凭据 | 凭据存 `markconfig/apprise.yml`（已在 .gitignore），提供 `apprise.example.yml` 模板 |

### 6.3 维护风险

| 风险 | 缓解 |
|------|------|
| 3 个 daemon（browser/reminder/scheduler）增加维护负担 | 统一 daemon 模式（HTTP API + 健康检查 + 崩溃重启），减少心智负担 |
| 与 v2.5 pattern_extractor 重复实现调度 | §5.5 已明确 v2.5 必须复用 v1.8 scheduler |
| 与 v3.5 重复实现本地控制 | §5.6 已明确 v3.5 必须复用 v1.8 browser daemon |
| 记忆文件 drift 再次发生 | Phase A 修复后，A4 的 PostToolUse hook 强制写入 |
