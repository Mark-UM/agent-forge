## 4. 架构验证

### 4.1 五层组装顺序

```
1. base.md              (priority 0,   always loaded)
2. profiles/{p}.md      (priority 50,  output style)
3. tasks/{t}.md         (priority 100, task-specific)
4. contexts/{c}.md      (priority 70-90, multiple allowed)
5. examples/{e}.md      (Few-Shot)
6. EXTRA (user profile) (markconfig/profile.md)
```

验证: `test_compose_full_stack` 确认 5 层顺序正确。

### 4.2 三通道集成

| 通道 | 触发 | 实现 | 状态 |
|------|------|------|------|
| A. Pre-Session | start-opencode.bat | `python -m modules.prompt.composer --pre-session` → AGENTS_COMPOSED.md | ✅ |
| B. In-Session | /mode 命令 | Agent 读取对应 prompt | ✅ |
| C. Auto-Detect | 消息关键词 | AGENTS.md 路由表 | ✅ |

### 4.3 A/B 测试闭环

```
/review → 3-stage pipeline → Score
    ↓
Post-Review Hook → experiments.py --log
    ↓
experiments.jsonl
    ↓
/prompt stats → 统计表
```

验证: 3 条实验记录已写入，`--stats` 输出正确。

### 4.4 调用模式验证（R3 新增）

所有 Python 模块 CLI 调用统一使用 `python -m modules.prompt.<module>` 形式：
- ✅ `start-opencode.bat` L49: `%PYTHON% -m modules.prompt.composer --pre-session`
- ✅ `manifest.json` entry_points: 全部使用 `python -m modules.prompt.*`
- ✅ `composer.py` docstring (R3 修正): `python -m modules.prompt.composer`
- ✅ `experiments.py` docstring: `python -m modules.prompt.experiments`
- ✅ `/prompt` 命令文档: `python -m modules.prompt.experiments --stats`

**原因**：`composer.py` L289 `from .log import ...` 是相对导入，仅在 `-m` 模式下有效。直接脚本调用 `python modules/prompt/composer.py --pre-session` 会 ImportError（R3 已验证）。

## 9. 已知限制

### 9.1 当前限制

1. **单用户场景**: experiments.jsonl 非原子写入，多用户并发可能丢数据
2. **Flash 分类成本**: 每次分类消耗 API token（默认关闭）
3. **手动上下文检测**: Agent 需主动判断文件类型并加载 context
4. **无 PII 脱敏**: task_description 原样存储（v3.0 计划引入）
5. **review.md hook 依赖 Agent 执行**: 钩子是指导性文档，非强制代码
6. **同秒实验 ID 冲突**: `exp-{timestamp}` 粒度为秒，同秒可能重复
7. **composer.py 不支持直接脚本调用**: 相对导入限制，必须用 `-m`（R3 文档化）
