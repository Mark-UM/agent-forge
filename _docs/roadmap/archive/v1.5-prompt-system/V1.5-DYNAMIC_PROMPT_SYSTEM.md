## 1. 规划背景与动机

### 1.1 现状（v1.0 基线）

| 维度 | 现状 | 等级 |
|------|------|------|
| 提示词载体 | `AGENTS.md` + `markconfig/profile.md` 静态加载 | ★★★☆☆ |
| 任务适配 | 所有任务加载相同 instructions，无任务类型感知 | ★★☆☆☆ |
| 上下文感知 | 无（不管修改 Python 还是 TypeScript，提示词不变） | ★☆☆☆☆ |
| Few-Shot 示例 | 67 个 skills 提供流程示例，但无代码示例库 | ★★☆☆☆ |
| 效果量化 | `/review` 输出 Score，但未与提示词版本关联 | ★★☆☆☆ |
| 可观测性 | 无提示词组装日志、无版本追踪 | ★☆☆☆☆ |

### 1.2 核心瓶颈

1. **静态加载**：`opencode.json` 的 `instructions` 字段在启动时加载，会话中无法切换
2. **任务无差别**：编程 / 审查 / 研究 / 调试 / 写作共用同一份 AGENTS.md，无法针对性优化
3. **技术栈盲区**：Python / TypeScript / Haskell / Java / C++ 无差异化提示，错失语言特异性最佳实践
4. **示例缺失**：缺乏高质量代码示例库，agent 输出一致性依赖模型先验
5. **无 A/B 量化**：提示词修改凭直觉，无 Score 对比数据支撑决策

### 1.3 v1.5 设计哲学

**借鉴 mattpocock-skills 的 `writing-great-skills` 核心原则**：

- **Predictability over Output**：动态组装追求**流程可预测**（同一任务类型走同一组装路径），而非输出一致
- **Progressive Disclosure**：分层加载，顶层 `base.md` 始终在上下文，`tasks/*.md` / `contexts/*.md` / `examples/*.md` 按需注入
- **Leading Words**：每个 task prompt 用强 leading word 锚定行为（如 `_red_` 锚定 TDD 红绿循环，_fog of war_ 锚定 wayfinder 规划）
- **Single Source of Truth**：每个规则只在一处定义，避免 duplication 与 sediment

**借鉴 obra-superpowers 的 `brainstorming` HARD-GATE 模式**：

- 关键任务（重构、架构变更、新功能）强制走"设计→批准→实施"流，禁止跳过
- 通过 `tasks/planning.md` 注入 HARD-GATE 指令

**借鉴 obra-superpowers 的 `subagent-driven-development` 模型选择原则**：

- 任务类型识别用 Flash（cheap），核心组装用 Pro（capable）
- 模型选择显式声明，避免静默继承 session 默认模型

### 1.4 设计原则（v1.5 特化）

延续 v4 升级的轻量化理念，但**适度放宽工程化与安全性**以聚焦提示词质量：

- **核心功能不简化**：每项能力都增强而非替代 AGENTS.md
- **声明式优先**：prompt 是 markdown 文件，组装逻辑是纯函数，避免 OOP 过度抽象
- **零外部依赖**：仅用 Python 标准库 + 已有 chromadb（v4.1 已引入）
- **工程化适度放宽**：单元测试覆盖关键路径即可（不强求 800+ tests），不强求类型注解全覆盖
- **安全性适度放宽**：PII 脱敏沿用 v4.0 既有方案，不为提示词系统单独引入新脱敏层
- **可观测**：每次组装写入 `_runtime/prompt/composition_log.jsonl`
- **可逆**：所有改动可通过删除 `modules/prompt/` + 还原 `AGENTS.md` 回滚

### 2.2 Claude Code / Anthropic 官方提示词工程最佳实践

借鉴 Anthropic 官方文档（`anthropic-best-practices.md` in obra-superpowers）：

| 原则 | 应用 |
|------|------|
| **Be explicit, not implicit** | 每个 task prompt 显式声明触发条件、流程、完成标准 |
| **Use XML tags for structure** | prompt 内部用 `<context>` / `<task>` / `<constraints>` / `<output>` 标签 |
| **Lead by example** | Few-Shot 示例优先于规则描述 |
| **Chain-of-Thought** | 复杂任务 prompt 内嵌 "Think step by before responding" |
| **Positive instructions** | 用"do X"替代"don't do Y"（obra writing-great-skills 同原则） |

### 5.2 详细设计

#### 5.2.1 `AGENTS_BASE.md` — 通用约束提取

从现有 `AGENTS.md` 提取以下部分（保留为最高优先级宪法）：

- Top Priority Directive（用户意图优先）
- Response Style（英文为主，中文解释复杂概念）
- Code Review Architecture（3 阶段强制审查）
- Vision and PDF Recognition Iron Rule
- Web Search Permission（三层策略）
- Context Management
- File Paths
- Personal Profile Summary

**保留 AGENTS.md 作为 OpenCode instructions 入口**，但内容精简为：
1. 加载 `AGENTS_BASE.md`（宪法）
2. 加载 `AGENTS_COMPOSED.md`（动态组装产物）
3. 任务路由指令（识别任务类型 → Read `.opencode/prompts/tasks/{type}.md`）

#### 5.2.2 `.opencode/prompts/base.md` — 基础约束（base 版本）

```markdown

priority: 0  # 最高优先级，始终加载

# Coding Task

## Trigger
- 用户请求实现功能 / 修复 bug / 添加测试
- 关键词："实现" / "修复" / "添加" / "refactor" / "implement" / "fix"

## Process

### 1. Identify the seam
Before writing code, identify the **seam** — the public boundary where behavior is observed. Tests live at seams, never against internals.

Ask: "What's the public interface, and which seams should we test?"

### 2. Red before green (TDD)
- Write the failing test first
- Only enough code to pass it
- Don't anticipate future tests or add speculative features
- One slice at a time: one seam, one test, one minimal implementation per cycle

### 3. Vertical slices, not horizontal
Work in **vertical slices** — one test → one implementation → repeat. Each test is a **tracer bullet** that responds to what the last cycle taught you.

Never write all tests first, then all implementation (horizontal slicing tests imagined behavior).

### 4. Refactoring is NOT part of the loop
Refactoring belongs to the review stage (see review.md), not the red → green implementation cycle.

## Anti-patterns to avoid
- **Implementation-coupled tests**: mocks internal collaborators, tests private methods → breaks on refactor
- **Tautological tests**: assertion recomputes expected value the way code does → passes by construction
- **Speculative generality**: abstraction/hooks for needs the spec doesn't have → delete it

## Completion criteria
- Every modified model accounted for (not "produce a change list")
- Each new behavior has a corresponding test at an agreed seam
- No speculative features added beyond spec
- Code review (`/review`) passes with Score ≥ 7/10

## Reference
- See `examples/python/test-driven.md` for TDD patterns
- See `examples/python/refactor-extract-method.md` for refactoring patterns

A change can pass one axis and fail the other. Report them **separately** to stop one axis masking the other.

### Axis 1: Standards
Does the code conform to this repo's documented coding standards?

Sources (in priority order):
1. Repo's `CODING_STANDARDS.md` / `CONTRIBUTING.md` if exists

   - Primitive Obsession → give concept its own type

   - Message Chains → hide walk
   - Middle Man → cut delegation
   - Refused Bequest → drop inheritance

### Axis 2: Spec
Does the code faithfully implement the originating issue / PRD / spec?

- (a) Requirements missing or partial
- (b) Behavior not asked for (scope creep)
- (c) Implementation looks wrong despite appearing implemented

1. **Pin the fixed point**: `git diff <fixed-point>...HEAD` (three-dot, against merge-base)
2. **Identify spec source**: issue references / PRD file / ask user
3. **Spawn both sub-agents in parallel** (review-standards + review-spec) — single message, two Agent tool calls
4. **Aggregate**: present under `## Standards` and `## Spec` headings verbatim; do NOT merge or rerank

## Completion criteria
- Total findings per axis reported
- Worst issue within each axis identified
- No single winner across axes (reranking defeats the separation)

This task integrates with the existing 3-stage review pipeline (review-code → review-structure → review-risk). Use `/review` to trigger the pipeline.

---

# Debugging Task

## Trigger
- 用户报告 bug / 异常 / 行为异常
- 关键词："bug" / "崩溃" / "异常" / "不工作" / "error" / "crash" / "fail"

## Iron Rule: Refuse to theorize until you have a tight feedback loop

A **tight loop** is one command that already goes **red** on *this* bug. Before any hypothesis:
1. Reproduce the bug with a single command
2. Confirm the reproduction is reliable (≥ 2 consecutive runs)

## Process

### 1. Reproduce (red)
- Write the smallest test that reproduces the bug
- The test must fail (red) on the current code
- If you can't reproduce → you can't fix; ask user for repro steps

### 2. Root-cause tracing
- **Never fix symptoms.** A symptom fix moves the bug, doesn't kill it.
- Use binary search / `git bisect` to locate the introducing commit
- Read the diff of the introducing commit
- Identify the **root cause** at the deepest layer

### 3. Fix at the root
- Fix the root cause, not the symptom
- The reproduction test must now pass (green)
- Add a regression test that would catch this bug class in the future

### 4. Defense in depth
- Ask: "What other code paths could trigger the same root cause?"
- Add assertions / guards at upstream boundaries
- Document the bug class in `_data/memory/lessons.md` (if exists)

## Anti-patterns
- **Shotgun fix**: changing 5 places hoping one works → indicates root cause not found
- **Symptom suppression**: try/except around the error → hides the bug
- **Fix without test**: "I'm sure it's fixed" → regression guaranteed

## Completion criteria
- Single reproduction test committed
- Root cause identified and documented (one sentence)
- Fix is minimal (touches only the root cause layer)
- Regression test added
- `/review` passes

## Reference
- obra `systematic-debugging` skill for full root-cause-tracing methodology

#### 5.2.11 `modules/prompt/composer.py` — 核心组装逻辑

```python
"""
Prompt Composer — 动态提示词组装引擎（v1.5 P0）

组装顺序（高优先级覆盖低优先级）：
1. base.md             （始终加载）
2. profile.md          （terse / detailed / socratic / default）
3. tasks/{type}.md     （任务类型特异）
4. contexts/{ctx}.md   （技术栈 / 目录特异，可多个）
5. examples/{...}.md   （Few-Shot，P1 引入）

CLI 用法：
    python modules/prompt/composer.py --pre-session
    python modules/prompt/composer.py --task coding --profile terse
    python modules/prompt/composer.py --list-tasks
"""
import json
import os
import sys
from datetime import datetime
from pathlib import Path
from typing import Optional

# 项目根目录
PROJECT_ROOT = Path(__file__).parent.parent.parent
PROMPTS_DIR = PROJECT_ROOT / ".opencode" / "prompts"
RUNTIME_DIR = PROJECT_ROOT / "_runtime" / "prompt"
AGENTS_COMPOSED = PROJECT_ROOT / "AGENTS_COMPOSED.md"

# 默认组装配置
DEFAULT_PROFILE = "default"
DEFAULT_TASK = None  # 启动时不加载 task，会话中按需加载


def load_prompt(path: Path) -> str:
    """加载 prompt 文件，去除 YAML frontmatter，返回正文。"""
    if not path.exists():
        return ""
    content = path.read_text(encoding="utf-8")
    if content.startswith("---"):
        end = content.find("---", 3)
        if end != -1:
            return content[end + 3:].lstrip()
    return content


def load_with_metadata(path: Path) -> dict:
    """加载 prompt 文件，返回 {content, metadata}。"""
    if not path.exists():
        return {"content": "", "metadata": {}}
    content = path.read_text(encoding="utf-8")
    metadata = {}
    if content.startswith("---"):
        end = content.find("---", 3)
        if end != -1:
            frontmatter = content[3:end].strip()
            content = content[end + 3:].lstrip()
            # 简单 YAML 解析（避免引入 PyYAML）
            for line in frontmatter.split("\n"):
                if ":" in line:
                    k, v = line.split(":", 1)
                    metadata[k.strip()] = v.strip()
    return {"content": content, "metadata": metadata}


def compose(
    profile: str = DEFAULT_PROFILE,
    task: Optional[str] = DEFAULT_TASK,
    contexts: Optional[list] = None,
    examples: Optional[list] = None,
    extra_instructions: Optional[str] = None,
) -> dict:
    """
    组装 prompt。

    Returns:
        {
            "prompt": str,           # 组装好的完整 prompt
            "sources": list[str],    # 加载的文件列表
            "metadata": dict,        # 版本、时间戳等
        }
    """
    sources = []
    parts = []

    # 1. Base (always loaded)
    base_path = PROMPTS_DIR / "base.md"
    base = load_prompt(base_path)
    if base:
        parts.append("# === BASE (Constitutional Layer) ===\n\n" + base)
        sources.append(str(base_path.relative_to(PROJECT_ROOT)))

    # 2. Profile
    profile_path = PROMPTS_DIR / "profiles" / f"{profile}.md"
    profile_content = load_prompt(profile_path)
    if profile_content:
        parts.append(f"# === PROFILE: {profile} ===\n\n" + profile_content)
        sources.append(str(profile_path.relative_to(PROJECT_ROOT)))

    # 3. Task
    if task:
        task_path = PROMPTS_DIR / "tasks" / f"{task}.md"
        task_content = load_prompt(task_path)
        if task_content:
            parts.append(f"# === TASK: {task} ===\n\n" + task_content)
            sources.append(str(task_path.relative_to(PROJECT_ROOT)))

    # 4. Contexts (multiple)
    if contexts:
        for ctx in contexts:
            ctx_path = PROMPTS_DIR / "contexts" / f"{ctx}.md"
            ctx_content = load_prompt(ctx_path)
            if ctx_content:
                parts.append(f"# === CONTEXT: {ctx} ===\n\n" + ctx_content)
                sources.append(str(ctx_path.relative_to(PROJECT_ROOT)))

    # 5. Examples (P1)
    if examples:
        for ex in examples:
            ex_path = PROMPTS_DIR / "examples" / f"{ex}.md"
            ex_content = load_prompt(ex_path)
            if ex_content:
                parts.append(f"# === EXAMPLE: {ex} ===\n\n" + ex_content)
                sources.append(str(ex_path.relative_to(PROJECT_ROOT)))

    # 6. Extra instructions (e.g., user profile from markconfig)
    if extra_instructions:
        parts.append("# === EXTRA ===\n\n" + extra_instructions)

    prompt = "\n\n---\n\n".join(parts)

    return {
        "prompt": prompt,
        "sources": sources,
        "metadata": {
            "version": "1.5.0",
            "composed_at": datetime.now().isoformat(),
            "profile": profile,
            "task": task,
            "contexts": contexts or [],
            "examples": examples or [],
        },
    }


def write_composed(result: dict, output_path: Path = AGENTS_COMPOSED) -> None:
    """将组装结果写入文件。"""
    output_path.parent.mkdir(parents=True, exist_ok=True)
    header = f"""<!-- Auto-generated by modules/prompt/composer.py at {result['metadata']['composed_at']} -->
<!-- Sources: {', '.join(result['sources'])} -->
<!-- Version: {result['metadata']['version']} -->

"""
    output_path.write_text(header + result["prompt"], encoding="utf-8")


def log_composition(result: dict) -> None:
    """记录组装日志到 _runtime/prompt/composition_log.jsonl。"""
    RUNTIME_DIR.mkdir(parents=True, exist_ok=True)
    log_path = RUNTIME_DIR / "composition_log.jsonl"
    entry = {
        **result["metadata"],
        "sources": result["sources"],
    }
    with open(log_path, "a", encoding="utf-8") as f:
        f.write(json.dumps(entry, ensure_ascii=False) + "\n")


def main():
    import argparse
    parser = argparse.ArgumentParser(description="Prompt Composer (v1.5)")
    parser.add_argument("--pre-session", action="store_true",
                        help="Pre-session composition for AGENTS_COMPOSED.md")
    parser.add_argument("--task", type=str, default=None,
                        help="Task type: coding|review|research|debugging|planning|writing|automation")
    parser.add_argument("--profile", type=str, default=DEFAULT_PROFILE,
                        help="Profile: default|terse|detailed|socratic")
    parser.add_argument("--context", action="append", default=[],
                        help="Context (can be repeated): python|typescript|secrets|memory|...")
    parser.add_argument("--example", action="append", default=[],
                        help="Example (can be repeated)")
    parser.add_argument("--list-tasks", action="store_true",
                        help="List available task prompts")
    parser.add_argument("--output", type=str, default=None,
                        help="Output file path (default: stdout)")
    args = parser.parse_args()

    if args.list_tasks:
        tasks_dir = PROMPTS_DIR / "tasks"
        if tasks_dir.exists():
            for f in sorted(tasks_dir.glob("*.md")):
                print(f.stem)
        return

    # 加载用户画像作为 extra instructions
    profile_path = PROJECT_ROOT / "markconfig" / "profile.md"
    extra = profile_path.read_text(encoding="utf-8") if profile_path.exists() else None

    result = compose(
        profile=args.profile,
        task=args.task,
        contexts=args.context or None,
        examples=args.example or None,
        extra_instructions=extra,
    )

    if args.pre_session:
        write_composed(result)
        log_composition(result)
        print(f"[OK] Composed → {AGENTS_COMPOSED}")
        print(f"[OK] Sources: {', '.join(result['sources'])}")
    elif args.output:
        write_composed(result, Path(args.output))
        log_composition(result)
        print(f"[OK] Composed → {args.output}")
    else:
        print(result["prompt"])
        log_composition(result)


if __name__ == "__main__":
    main()
```

"""
Context Detector — 检测当前会话的上下文信号（v1.5 P0）

信号维度：
- file_extension: .py / .ts / .hs / .java / .cpp
- file_directory: markconfig/ / _data/memory/ / modules/ / .opencode/
- session_length: short / medium / long
- keywords: 修复 / 审查 / 搜索 / 重构 / 设计
- cross_directory: filesystem MCP 调用模式
"""
import re
from pathlib import Path
from typing import Optional

PROJECT_ROOT = Path(__file__).parent.parent.parent


def detect_file_extension(file_path: str) -> Optional[str]:
    """从文件路径检测编程语言。"""
    ext_map = {
        ".py": "python",
        ".ts": "typescript",
        ".tsx": "typescript",
        ".hs": "haskell",
        ".java": "java",
        ".cpp": "cpp",
        ".cc": "cpp",
        ".cxx": "cpp",
        ".h": "cpp",
    }
    ext = Path(file_path).suffix.lower()
    return ext_map.get(ext)


def detect_file_directory(file_path: str) -> Optional[str]:
    """从文件路径检测目录上下文。"""
    abs_path = Path(file_path).resolve()
    try:
        rel = abs_path.relative_to(PROJECT_ROOT)
    except ValueError:
        return None

    parts = rel.parts
    if not parts:
        return None

    top = parts[0]
    if top == "markconfig":
        return "secrets"
    if top == "_data" and len(parts) > 1 and parts[1] == "memory":
        return "memory"
    if top == "modules":
        return "modules"
    if top == ".opencode":
        return "opencode"
    if top == "_runtime":
        return "runtime"
    return None


def detect_session_length(turn_count: int) -> str:
    """根据会话轮数判断长度。"""
    if turn_count < 10:
        return "short"
    if turn_count < 50:
        return "medium"
    return "long"


def detect_keywords(message: str) -> list:
    """从用户消息检测任务关键词。"""
    keywords_map = {
        "coding": ["实现", "修复", "添加", "implement", "fix", "add", "refactor"],
        "review": ["审查", "review", "PR", "diff"],
        "research": ["搜索", "调研", "research", "compare", "对比", "查"],
        "debugging": ["bug", "崩溃", "异常", "error", "crash", "fail"],
        "planning": ["设计", "规划", "plan", "architecture", "架构"],
        "writing": ["文档", "报告", "write", "document"],
        "automation": ["浏览器", "browser", "自动化", "automate"],
    }
    detected = []
    msg_lower = message.lower()
    for task, kws in keywords_map.items():
        for kw in kws:
            if kw.lower() in msg_lower:
                detected.append(task)
                break
    return detected


def detect_context_signals(
    message: str,
    file_paths: Optional[list] = None,
    turn_count: int = 0,
) -> dict:
    """
    综合检测上下文信号。

    Returns:
        {
            "languages": list[str],      # 检测到的编程语言
            "directories": list[str],    # 检测到的目录上下文
            "session_length": str,       # short / medium / long
            "task_hints": list[str],     # 关键词匹配的 task 类型
        }
    """
    languages = set()
    directories = set()

    if file_paths:
        for fp in file_paths:
            lang = detect_file_extension(fp)
            if lang:
                languages.add(lang)
            dir_ctx = detect_file_directory(fp)
            if dir_ctx:
                directories.add(dir_ctx)

    return {
        "languages": sorted(languages),
        "directories": sorted(directories),
        "session_length": detect_session_length(turn_count),
        "task_hints": detect_keywords(message),
    }


def suggest_contexts(signals: dict) -> list:
    """根据信号建议要加载的 contexts。"""
    contexts = []
    for lang in signals["languages"]:
        contexts.append(lang)
    for d in signals["directories"]:
        if d in ("secrets", "memory"):
            contexts.append(d)
    if signals["session_length"] == "long":
        contexts.append("long-session")
    return contexts


def suggest_task(signals: dict) -> Optional[str]:
    """根据信号建议 task 类型（取第一个匹配）。"""
    if signals["task_hints"]:
        return signals["task_hints"][0]
    return None
```

#### 5.2.13 `modules/prompt/classify.py` — 任务类型分类

```python
"""
Task Classifier — 任务类型分类（v1.5 P0）

两种模式：
- heuristic（默认，零成本）：关键词规则匹配（context.detect_keywords）
- flash（--classify-mode flash）：DeepSeek V4 Flash 分类

Flash 模式 prompt 借鉴 v4.0 search Planner 集成方式：
- 输出严格 JSON
- 失败降级到 heuristic
"""
import json
import os
import urllib.request
from typing import Optional

from . import context


CLASSIFY_PROMPT_TEMPLATE = """You are a task classifier. Given the user message, classify it into exactly one task type.

## Task Types
- coding: implementing features, fixing bugs, adding tests, refactoring
- review: code review, PR review, diff review
- research: web search, technical research, comparison
- debugging: bug investigation, crash analysis, error tracing
- planning: design, architecture, large feature planning
- writing: documentation, reports, prose
- automation: browser automation, system automation

## Output Format (STRICT JSON, no markdown fences)

{
  "task_type": "<one of: coding|review|research|debugging|planning|writing|automation>",
  "confidence": <0.0-1.0>,
  "rationale": "<one short sentence>"
}

## User Message
{user_message}
"""


def classify_heuristic(message: str) -> str:
    """启发式分类（关键词匹配）。"""
    signals = context.detect_context_signals(message)
    if signals["task_hints"]:
        return signals["task_hints"][0]
    return "coding"  # 默认


def classify_flash(message: str, timeout: int = 15) -> Optional[str]:
    """Flash 模型分类（失败返回 None，调用方降级到 heuristic）。"""
    api_key = os.environ.get("DEEPSEEK_API_KEY") or os.environ.get("ANTHROPIC_AUTH_TOKEN")
    if not api_key:
        return None

    prompt = CLASSIFY_PROMPT_TEMPLATE.format(user_message=message)
    payload = {
        "model": "deepseek-chat",
        "messages": [{"role": "user", "content": prompt}],
        "temperature": 0.0,
        "max_tokens": 100,
        "stream": False,
    }

    try:
        req = urllib.request.Request(
            "https://api.deepseek.com/v1/chat/completions",
            data=json.dumps(payload).encode("utf-8"),
            headers={
                "Authorization": f"Bearer {api_key}",
                "Content-Type": "application/json",
            },
            method="POST",
        )
        with urllib.request.urlopen(req, timeout=timeout) as resp:
            data = json.loads(resp.read().decode("utf-8"))
        content = data["choices"][0]["message"]["content"].strip()
        # 解析 JSON（容忍 markdown fences）
        if content.startswith("```"):
            content = content.split("\n", 1)[1].rsplit("```", 1)[0]
        result = json.loads(content)
        task = result.get("task_type", "").strip().lower()
        if task in ("coding", "review", "research", "debugging", "planning", "writing", "automation"):
            return task
        return None
    except Exception:
        return None


def classify(message: str, mode: str = "heuristic") -> str:
    """
    分类任务类型。

    Args:
        message: 用户消息
        mode: "heuristic" | "flash"

    Returns:
        task_type string
    """
    if mode == "flash":
        result = classify_flash(message)
        if result:
            return result
        # 降级到 heuristic
    return classify_heuristic(message)
```

def fibonacci(n: int) -> int:

### 7.3 `modules/prompt/experiments.py`

```python
"""
Prompt Experiments — A/B 测试与效果量化（v1.5 P2）

数据源：
- _runtime/prompt/experiments.jsonl  （实验记录）
- _runtime/prompt/composition_log.jsonl  （组装记录）

关联：
- /review 输出的 Score 自动写入 experiments
"""
import json
from collections import defaultdict
from datetime import datetime
from pathlib import Path
from typing import Optional

RUNTIME_DIR = Path(__file__).parent.parent.parent / "_runtime" / "prompt"
EXPERIMENTS_PATH = RUNTIME_DIR / "experiments.jsonl"


def log_experiment(
    task_type: str,
    profile: str,
    contexts: list,
    examples: list,
    task_description: str,
    review_score: Optional[float] = None,
    review_findings: Optional[dict] = None,
    duration_seconds: Optional[int] = None,
    tokens_used: Optional[int] = None,
    user_satisfied: Optional[bool] = None,
    user_feedback: Optional[str] = None,
) -> str:
    """记录一次实验。返回 experiment_id。"""
    RUNTIME_DIR.mkdir(parents=True, exist_ok=True)
    experiment_id = f"exp-{int(datetime.now().timestamp())}"
    entry = {
        "experiment_id": experiment_id,
        "timestamp": datetime.now().isoformat(),
        "prompt_version": "1.5.0",
        "task_type": task_type,
        "profile": profile,
        "contexts": contexts,
        "examples": examples,
        "task_description": task_description,
        "outcome": {
            "review_score": review_score,
            "review_findings_critical": review_findings.get("critical", 0) if review_findings else 0,
            "review_findings_major": review_findings.get("major", 0) if review_findings else 0,
            "review_findings_minor": review_findings.get("minor", 0) if review_findings else 0,
            "duration_seconds": duration_seconds,
            "tokens_used": tokens_used,
            "user_satisfied": user_satisfied,
        },
        "user_feedback": user_feedback,
    }
    with open(EXPERIMENTS_PATH, "a", encoding="utf-8") as f:
        f.write(json.dumps(entry, ensure_ascii=False) + "\n")
    return experiment_id


def compute_stats() -> dict:
    """计算统计数据。"""
    if not EXPERIMENTS_PATH.exists():
        return {"total": 0}

    entries = []
    with open(EXPERIMENTS_PATH, "r", encoding="utf-8") as f:
        for line in f:
            try:
                entries.append(json.loads(line))
            except json.JSONDecodeError:
                continue

    if not entries:
        return {"total": 0}

    # 按 task_type 分组统计
    by_task = defaultdict(list)
    for e in entries:
        score = e.get("outcome", {}).get("review_score")
        if score is not None:
            by_task[e["task_type"]].append(score)

    stats = {
        "total": len(entries),
        "by_task_type": {},
        "overall_avg_score": 0.0,
    }
    all_scores = []
    for task, scores in by_task.items():
        avg = sum(scores) / len(scores)
        stats["by_task_type"][task] = {
            "count": len(scores),
            "avg_score": round(avg, 2),
            "min_score": min(scores),
            "max_score": max(scores),
        }
        all_scores.extend(scores)

    if all_scores:
        stats["overall_avg_score"] = round(sum(all_scores) / len(all_scores), 2)

    return stats


def render_stats_markdown() -> str:
    """渲染统计为 Markdown（供 /prompt stats 命令使用）。"""
    stats = compute_stats()
    if stats["total"] == 0:
        return "No experiments recorded yet."

    lines = [
        "# Prompt Experiment Stats",
        "",
        f"**Total experiments**: {stats['total']}",
        f"**Overall average score**: {stats['overall_avg_score']}/10",
        "",
        "## By Task Type",
        "",
        "| Task | Count | Avg Score | Min | Max |",
        "|------|-------|-----------|-----|-----|",
    ]
    for task, s in sorted(stats["by_task_type"].items()):
        lines.append(f"| {task} | {s['count']} | {s['avg_score']} | {s['min_score']} | {s['max_score']} |")

    return "\n".join(lines)
```

## 10. 关键决策记录

### 决策 1：三种集成通道并存（A + B + C）

**选择**：Pre-Session（A） + `/mode` 命令（B） + Agent 自动检测（C）并存

**原因**：
- A 解决"启动时静态加载"限制
- B 解决"会话中无法切换"限制
- C 解决"任务类型识别"问题
- 三者互补，不冲突
- OpenCode 原生不支持动态 instructions，三通道组合是最佳折衷

### 决策 2：保留 AGENTS.md 作为入口

**选择**：AGENTS.md 精简为入口，不删除

**原因**：
- OpenCode 的 `instructions` 字段需要至少一个稳定入口
- AGENTS.md 是所有 OpenCode 用户的约定俗成
- 删除会破坏现有 v4.3 集成（search-orchestration SKILL 引用 AGENTS.md）

### 决策 3：YAML frontmatter 用简单解析（不引入 PyYAML）

**选择**：composer.py 用字符串解析 frontmatter

**原因**：
- 项目零外部依赖原则
- frontmatter 字段简单（key: value），无需复杂 YAML 解析
- 失败时降级到无 metadata，不影响组装

### 决策 4：Flash 分类作为可选模式

**选择**：默认 heuristic，`--classify-mode flash` 显式开启

**原因**：
- heuristic 零成本，覆盖 80% 场景
- Flash 模式增加 1-2s 延迟 + ~$0.0001 成本
- 复杂查询才需要 Flash 分类
- 与 v4.0 search Planner 的双轨模式一致

### 决策 5：借鉴 mattpocock writing-great-skills 而非自创

**选择**：直接采用 mattpocock 的信息层级 / leading words / progressive disclosure 概念

**原因**：
- mattpocock skills 是社区公认的提示词工程最佳实践
- 已集成在项目中，无需额外学习成本
- 避免重复造轮子

### 决策 6：A/B 测试用 JSONL 而非数据库

**选择**：`_runtime/prompt/experiments.jsonl` 文件存储

**原因**：
- 与 v4.3 search 历史日志格式一致
- 无需引入数据库依赖
- 数据量小（每月 ~100 条实验记录）
- 可用 `jq` / Python 标准库分析

### 决策 7：适度放宽工程化（用户明确要求）

**选择**：不强求 800+ tests，不强求全类型注解，不强求 property-based testing

**原因**：
- 用户明确要求"对于安全性与工程化可以适度放宽"
- 聚焦提示词质量，而非测试覆盖率
- 保留 3-stage review pipeline 作为质量底线
- 单元测试覆盖关键路径即可（P0: 30-50 tests, P1-P3: 15-20 each）

### 决策 8：HARD-GATE 仅用于 planning 任务

**选择**：HARD-GATE 注入到 `tasks/planning.md`，不全局强制

**原因**：
- HARD-GATE 来自 obra brainstorming，适用于设计阶段
- 编程 / 调试 / 审查任务不需要强制设计审批
- 全局 HARD-GATE 会阻碍快速迭代
