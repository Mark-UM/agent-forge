# Archived Plan: V1.7 — 质量深化与开源融合执行规划

> Historical plan. Not a current specification or status report.

> **版本**：v1.7.0
> **阶段类型**：质量升级（Quality + Open Source Integration）
> **预计周期**：3-4 周
> **前置条件**：v1.6 验收通过（0 遗留漏洞 + 文档对齐 + review hook 强制化）
> **核心目标**：Context Engineering 升级到 A+，路由准确率 95%+，引入开源工具补齐短板
> **核心策略**：高质量开源项目融合 + 自研轻量补丁

---

## 1. 背景与必要性

### 1.1 为何需要 v1.7

v1.6 巩固了基础，但项目仍有三大短板（来自全球 SOTA 对标分析）：

1. **Context Engineering 仅 A 级**：缺少向量检索，长会话 token 浪费严重
2. **路由准确率有限**：classify.py Flash 模式默认关闭，靠关键词匹配准确率约 80%
3. **Skills 数量不足**：实际 32 个 vs SOTA 个人项目 50+，README 声称 67 但 obra/vercel 未拉取

v1.7 通过**融合开源工具**解决这三个短板，为 v2.0 Multi-Agent 铺路。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| 开源优先 | 能用开源组件就用，不自研重复轮子 |
| 零核心依赖 | 核心模块（composer/classify）保持 stdlib only，开源组件作为可选扩展 |
| PoC 验证 | 每个开源组件先做 PoC，验证后再集成 |
| 成本敏感 | API 调用需成本估算，本地优先 |
| 可替换性 | 任何开源组件必须有 fallback 方案 |

## 2. 任务清单

### 2.1 P0 任务（必须完成）

#### P0-1: 长会话向量检索压缩（Context Engineering A+）

**问题**：当前长会话（>50 轮）依赖 `contexts/long-session.md` 静态提示 + DCP plugin 裁剪，缺少基于语义的检索。SOTA（Cursor / Claude Code）已有 progressive context summarization。

**修复方案**：
- 复用已有 ChromaDB（v4.1 搜索系统已引入）
- 新增 `modules/prompt/context_retrieval.py`：
  - 接收会话历史，分块嵌入到 ChromaDB
  - 用户新消息作为 query，检索 top-k 相关历史片段
  - 与 DCP 裁剪协同：先检索召回 → 再 DCP 裁剪
- 集成 LlamaIndex 的 `VectorStoreIndex` 作为高级接口（可选）
- Embedding 模型：all-MiniLM-L6-v2（本地，已使用）

**开源工具**：
- ChromaDB（已有，Apache 2.0）
- LlamaIndex（MIT，可选，作为高级封装）
- all-MiniLM-L6-v2（已有，本地）

**影响文件**：
- `modules/prompt/context_retrieval.py`（新增）
- `modules/prompt/context.py`（修改，集成检索）
- `modules/prompt/tests/test_context_retrieval.py`（新增）
- `modules/prompt/manifest.json`（更新）
- `.opencode/prompts/contexts/long-session.md`（更新，引用检索能力）

**验收**：
- 长会话（50+ 轮）token 消耗下降 ≥ 40%（对比 v1.6 基线）
- 检索相关性 top-5 命中率 ≥ 80%（人工评估 20 case）
- 测试 ≥ 15 个
- 检索延迟 < 500ms

#### P0-2: 启用 classify Flash 模式默认 + 缓存优化

**问题**：`classify.py` 支持 Flash 模式（准确率 95%+）但默认关闭，靠关键词匹配（准确率约 80%）。L7 遗留问题。

**修复方案**：
- 修改 `classify.py` 默认 mode 从 `heuristic` 改为 `flash`
- 新增 LRU 缓存层（复用 search 模块的 LRU 500 模式）
- 缓存 key：hash(message + mode)
- 缓存 TTL：24h
- Flash 失败时自动降级到 heuristic（已有逻辑）
- 成本估算：每次 Flash 调用 ~$0.0001，日均 50 次分类 = $0.005/天 = $1.5/月

**开源工具**：
- 无（自研 + DeepSeek Flash API）

**影响文件**：
- `modules/prompt/classify.py`（修改）
- `modules/prompt/tests/test_classify.py`（新增缓存测试）
- `.opencode/prompts/router.md`（更新，说明 Flash 默认）

**验收**：
- 任务路由准确率 ≥ 95%（100 case 测试集，对比 heuristic 80%）
- 缓存命中率 ≥ 60%（重复任务场景）
- 日均 Flash 调用成本 < $0.01
- 测试 ≥ 5 个新增
