# 2.0 Lightweight Multi-Agent Kernel Execution Plan

Status date: 2026-08-06.

This is a planning contract. It does not describe implemented Kernel behavior,
select a framework, create a database schema, or authorize production code.

- **Implementation:** Not implemented.

## 2. Goal

Agent Forge 2.0 evolves the current single coding Agent plus human-controlled
review procedures into a small, typed Agent Kernel. It must make multi-step
coordination explicit, bounded, observable, and testable without creating a
second platform beside the existing workspace.

```text
ordinary short task
    -> direct function, CLI, MCP, or tool call

bounded multi-step task
    -> Kernel Task
       -> Coordinator
       -> Worker or Agent-as-tool
       -> explicit Handoff when ownership changes
       -> Reviewer/Tester
       -> Artifact and Approval records
       -> terminal Task state
```

The Kernel must preserve current OpenCode, CLI, MCP, and single-Agent behavior;
reuse existing capability services; remain Windows-first on Python 3.11; and
avoid orchestration where a direct call is safer and simpler.

## 3. Deliverables

2.0 is planned to deliver:

1. `Task` with objective, normalized input, status, owner, budgets, checkpoints,
   Artifact/Approval references, and terminal outcome.
2. `AgentSpec` defining role, capabilities, tools, model policy, permissions,
   concurrency, budgets, and typed I/O.
3. `Handoff` for explicit, idempotent transfer of bounded context, budget, and
   acceptance criteria.
4. `Artifact` with producer, digest, provenance, validation, sensitivity, and
   retention metadata.
5. `Approval` with scoped request, decision, expiry, decision maker, and audit
   reference.
6. a small Coordinator that decomposes only when needed;
7. a Worker restricted to allowed tools and Workspace;
8. one combined Reviewer/Tester that accepts, rejects with bounded feedback, or
   records degraded output;
9. Agent-as-tool, where the caller retains ownership;
10. explicit persisted Handoff, where ownership changes;
11. finite step, token, wall-clock, retry, tool-call, Agent, and child-Task
    budgets;
12. one SQLite Task/checkpoint authority, semantically separate from Search,
    Scheduler, Memory, and Supervisor state;
13. one deterministic single-file text maintenance Task completed end to end
    without modifying or merging `main`.

## 4. Non-goals

2.0 does not include:

- A2A federation or external Agent discovery;
- a Dashboard or hosted control plane;
- distributed queues, Kubernetes, or remote worker fleets;
- autonomous modification, push, merge, or protection changes on `main`;
- ten or more permanent Agent roles;
- two production orchestration frameworks;
- fixing SiliconFlow Vision as a Kernel release prerequisite;
- complete 2.1 durable worktree, pause/resume, crash recovery, and rollback;
- 2.2 capability aggregation;
- 2.3 Search/Context/Memory convergence;
- replacement of OpenCode, MCP, Runtime Supervisor, or current capability
  services;
- enterprise RBAC or a general policy engine;
- using Agent count, abstraction count, or hand-written test totals as evidence.

## 5. Architecture principles

### Reuse before replacement

- Model policy and endpoint ownership remain in `modules.dispatch.gateway`.
- Run lifecycle and local telemetry reuse `modules.common` Run/Step/Event.
- Search, Browser, Memory, and Scheduler are consumed through canonical APIs and
  existing security boundaries.
- Browser/Scheduler process ownership remains in `modules.runtime.supervisor`.
- Capability discovery and Manifest validation remain in `modules.registry`.

### One authority per state domain

- Kernel Task/checkpoint tables have one authority contract.
- Search cache, Scheduler jobs/runs, Memory candidates, Browser profile, Prompt
  state, and Supervisor ownership are not copied into Kernel-owned state.
- A physical SQLite file may be shared only if schemas, transactions,
  migrations, and authority semantics stay independent.
- Temporary migration readers may exist; indefinite dual-write is prohibited.

### Bounded and explicit execution

- Every budget is finite by default.
- Handoff is persisted and explicit; conversation implication is not ownership
  transfer.
- Artifact identity, provenance, digest, validation, and supersession are
  traceable.
- Approval is scoped, expiring where applicable, and auditable.
- Agent/tool subprocesses have timeout, cancellation, output, and cleanup bounds.

### Security and truthful outcomes

- Agents cannot directly modify `main`.
- Writes remain in an assigned Workspace and permission scope.
- Network access continues through existing Gateway, Search, Browser, Fetch,
  and MCP boundaries.
- Missing optional Providers become unavailable/degraded, never fake success.
- Private Memory is opt-in by AgentSpec and Task, not shared globally.

### Small surface area

- Add the fewest concepts needed for reliable coordination.
- Ordinary short work remains direct when orchestration adds no safety or
  evidence.
- Framework objects stay behind one thin Adapter and are not persisted as domain
  contracts.

## 6. Proposed package boundary

No package is created by this planning PR. The provisional boundary is one new
first-party module, tentatively `modules/kernel/`, because 2.0 introduces a
distinct production lifecycle and Task/checkpoint authority. The final package
name is a decision Gate and requires one canonical Manifest if implemented.

The Kernel should own framework-neutral Task, TaskCheckpoint, AgentSpec,
Handoff, Artifact, Approval, Budget, Coordinator/Worker/Reviewer command/result,
repository, transaction, and Adapter protocols.

Existing modules remain authoritative:

| Module | Responsibility retained |
|---|---|
| `modules.dispatch` | model selection, endpoint ownership, request normalization, retries/timeouts, redaction, Provider errors |
| `modules.common` | shared security utilities and Run/Step/Event |
| `modules.runtime` | Browser/Scheduler lifecycle and process ownership |
| `modules.registry` | Manifest/capability discovery and validation |
| `modules.search` | Search planning, readiness, fallback, result/cache authority |
| `modules.browser`, `modules.mcp` | bounded Browser/network tools |
| `modules.scheduler` | scheduled job and job-run authority |
| `modules.memory` | Memory candidate Approval and durable private Memory |
| `modules.orchestrator` | current collection/action/index/schedule adapters until deliberately migrated |

The Kernel must not duplicate a model HTTP client, Gateway retry/redaction
policy, Search Provider/cache, Browser/Scheduler lifecycle, Memory persistence,
Registry, or a second tracing system. Framework session/checkpoint storage must
remain non-authoritative and replaceable or the framework fails selection.

## 7. Delivery slices

Each Slice is one reviewable PR. It starts only after predecessor exit criteria
are met on the exact current head.

### Slice 0 — Documents, contracts, and selection preparation

- **Goal:** freeze scope, state contracts, PoC equivalence, acceptance evidence,
  and decisions.
- **Change scope:** maintained planning docs, corrected onboarding, Roadmap links.
- **Dependencies:** completed foundation and current architecture/Manifests.
- **Tests:** docs consistency, `git diff --check`, compile, Registry strict,
  no-bypass, and confirmation that only docs changed.
- **Exit:** reviewers accept contracts and decision Gates; no code, dependency,
  schema, test, or Workflow change.
- **Rollback:** revert the docs-only commit.
- **Excluded:** framework install/PoC execution and all implementation.

### Slice 1 — Core types and Task state storage

- **Goal:** framework-neutral types, transitions, and one SQLite Task/checkpoint
  repository.
- **Scope:** one approved Kernel package/Manifest, typed contracts, repository,
  versioned Kernel-only schema, unit/transaction tests.
- **Dependencies:** accepted state machine and SQLite ADR.
- **Tests:** validation, illegal transitions, rollback, concurrency,
  idempotency, digest, Windows temporary SQLite, Registry strict.
- **Exit:** unique authority; no model/framework dependency; duplicates rejected;
  existing state domains unchanged.
- **Rollback:** revert unshipped module/migration while test DBs are disposable.
- **Excluded:** model calls, Handoffs, framework Adapter, E2E file work.

### Slice 2 — Minimal Coordinator/Worker execution

- **Goal:** bounded Coordinator and Worker using deterministic model/tool stubs.
- **Scope:** framework-neutral execution loop, AgentSpec permission checks,
  typed plan/command/result, Task-to-Run mapping.
- **Dependencies:** Slice 1.
- **Tests:** deterministic allocation, direct-call decision, success/failure,
  cancellation, timeout, duplicate execution; no real Provider.
- **Exit:** one Coordinator/Worker scenario completes under finite budgets;
  ordinary direct calls remain supported.
- **Rollback:** revert execution components; test records remain readable as
  unsupported/abandoned.
- **Excluded:** explicit Handoff, durable Artifact/Approval, Reviewer, framework.

### Slice 3 — Handoff, Artifact, and Approval

- **Goal:** explicit ownership transfer, traceable Artifacts, bounded decisions.
- **Scope:** repositories/transitions, Workspace path/digest enforcement,
  Approval request/decision, idempotency/audit references.
- **Dependencies:** Slices 1–2.
- **Tests:** duplicate Handoff consumption; Artifact collision/digest/path escape;
  Approval allow/deny/expiry/cancel/duplicate; transaction failures.
- **Exit:** ownership changes only through accepted Handoff; silent overwrite is
  impossible; required side effects wait for Approval; no Secret metadata.
- **Rollback:** disable entry points and revert while preserving append-audited
  records according to a downgrade plan.
- **Excluded:** Reviewer loops and framework selection.

### Slice 4 — Reviewer/Tester and budgets

- **Goal:** combined review role and complete parent/child budget enforcement.
- **Scope:** typed review outcomes, bounded rework, budget ledger and transfer.
- **Dependencies:** Slices 2–3.
- **Tests:** all budget types, one rejection/rework, cancellation propagation,
  usage reconciliation with Gateway metadata.
- **Exit:** no unbounded loop; Reviewer cannot mutate Worker output silently;
  degraded and accepted outcomes differ; evidence maps to Run/Step/Event.
- **Rollback:** disable multi-Agent entry points and revert Reviewer/budgets.
- **Excluded:** live Provider and third-party framework.

### Slice 5 — Selected framework thin Adapter

- **Goal:** after an independent ADR selects one option, add only its Adapter.
- **Scope:** exactly one production framework dependency, model/tool/Handoff/
  telemetry translation, lock update, focused tests.
- **Dependencies:** completed equivalent PoCs, approved ADR, Slices 1–4.
- **Tests:** Gateway-only model path; no direct endpoint; Agent-as-tool/Handoff;
  cancellation, timeout, retries, usage, typed output, MCP stub, telemetry;
  Windows 3.11 import/startup and clean install.
- **Exit:** all hard Gates pass; unselected framework absent; framework state and
  tracing cannot replace authority or leak data; Adapter is removable.
- **Rollback:** remove Adapter/dependency and use framework-neutral reference path.
- **Excluded:** dual frameworks and 2.1 durability.

### Slice 6 — Single-file end-to-end Task

- **Goal:** complete one text maintenance Task in an isolated Workspace.
- **Scope:** one explicit Kernel entry point, Workspace Adapter, deterministic
  fixture/stub, E2E evidence.
- **Dependencies:** Slices 1–5.
- **Tests:** Coordinator plan, one-file Worker edit, Reviewer checks, Artifact
  digest/provenance, no commit/push/merge; rejection, timeout, duplicate, restart
  boundary; no Vision or real Secret.
- **Exit:** truthful terminal state and audit evidence; outside Workspace
  unchanged; idempotency prevents repeated side effects; no residual process/port.
- **Rollback:** disable entry point and remove isolated output.
- **Excluded:** arbitrary repositories, multiple files, live Vision, full resume.

### Slice 7 — Windows CI, release docs, and closeout

- **Goal:** make completed 2.0 reproducible on the release platform.
- **Scope:** focused Workflow/Windows additions only after implementation is
  stable; maintained docs and exact-head report contract.
- **Dependencies:** Slice 6 accepted locally and in normal CI.
- **Tests:** full existing suite plus Kernel tests; clean Windows 3.11 install;
  Registry/no-bypass; process/port/Workspace/Secret cleanup; exact SHA evidence.
- **Exit:** all blocking matrix rows pass for one exact head; local-only Provider
  evidence separated; docs distinguish 2.0 from 2.1–2.3; no obsolete candidate.
- **Rollback:** revert release integration and keep Kernel entry point disabled;
  never weaken foundation checks.
- **Excluded:** 2.1–2.3 implementation.

## 9. Backward compatibility

- Current OpenCode, CLI, MCP, Search, Browser, Scheduler, Memory, and Delivery
  paths continue without the Kernel.
- Short direct/single-Agent tasks are not forced into multi-Agent records.
- Existing state domains are not migrated to a second authority.
- Old entries may delegate to canonical implementations, but never become a new
  primary path.
- Temporary migration reading is bounded; long-term dual-write is forbidden.
- Framework sessions/traces/checkpoints remain replaceable and non-authoritative.
- Disabling/removing Kernel leaves current single-Agent behavior operational.

## 10. Security model

- Task/Handoff/Artifact/Approval/Run metadata excludes raw prompts, responses,
  credentials, cookies, private Memory, and token-like values.
- Every write-capable Agent receives one resolved Workspace root and explicit
  path/tool permissions. Traversal, symlink/junction escape, `.git`, `main`, and
  authority-file writes are denied unless separately scoped and approved.
- Network calls retain existing Gateway/Search/Browser/Fetch/MCP URL, DNS, IP,
  redirect, auth, size, retry, and timeout boundaries.
- AgentSpec tool allowlists cannot be widened by the model or Handoff.
- Subprocesses use explicit executables/arguments, bounded environment/output,
  timeout, cancellation, and process-tree cleanup.
- Read-only work needs no ceremony; external side effects, publication, private
  Memory, credential-bearing use, and protected writes follow scoped Approval.
- Kernel never auto-commits, pushes, marks PR Ready, changes protection, or
  merges `main`.
- Private Memory read/write must be explicitly granted and durable writes still
  use the existing Memory candidate Approval path.

## 11. Observability

Kernel uses existing Run/Step/Event rather than a second telemetry system:

| Kernel concept | Mapping |
|---|---|
| Task | top-level Run correlated by `task_id`; terminal outcomes agree |
| Agent execution | Step with Agent, role, attempt, usage, and parent Task |
| Handoff | requested/accepted/rejected/consumed Events and target Step |
| Artifact | lifecycle Events with ID/digest, never unrestricted content |
| Approval | request/decision/expiry/consumption Events with audit reference |
| Budget | reservation, usage, remaining snapshot, and exhaustion Events |
| failure/degraded/cancel/timeout/abandon | normalized Events and terminal reduction |

Task SQLite remains authoritative if telemetry is degraded. Framework trace IDs
may be optional references only; sensitive remote tracing is disabled by default.

## 12. Vision Provider known issue

SiliconFlow `Qwen/Qwen3-VL-Plus` local acceptance currently fails with a
`RuntimeError`.

- Evidence is insufficient to attribute a specific cause.
- It does not block the 2.0 text core loop.
- The first E2E Task must not depend on image/PDF recognition.
- Diagnosis remains a separate Provider issue.
- Kernel capability state must represent optional Vision as unavailable or
  degraded and must fail explicitly when Vision is required.

## 13. Definition of Done

2.0 is complete only when one reviewed exact head proves all of the following:

- all domain contracts, legal transitions, normalized failures, transaction,
  concurrency, idempotency, and migration behavior are implemented;
- one SQLite Task/checkpoint authority exists and other authorities are unchanged;
- Coordinator, Worker, and Reviewer/Tester use typed I/O;
- Agent-as-tool and Handoff are distinct and tested;
- all budgets are finite and cancellation/timeout reach active children/tools;
- optional Provider absence yields truthful unavailable/degraded behavior;
- one framework or a justified thinner self-owned Kernel is selected by ADR;
- at most one third-party orchestration framework is a production dependency;
- all model traffic stays behind `modules.dispatch.gateway`;
- framework state is non-authoritative, tracing is safe by default, and Adapter
  removal does not rewrite domain records;
- Workspace, network, tool, Secret, private Memory, subprocess, and Approval
  boundaries pass blocking acceptance;
- no Agent can autonomously modify or merge `main`;
- current OpenCode/CLI/MCP/single-Agent paths continue to pass;
- no permanent dual-write or alternate endpoint/cache/lifecycle path exists;
- the deterministic single-file text E2E completes with Artifact, review,
  budgets, telemetry, failure injections, cleanup, and no Vision/real Secret;
- exact-head unit, contract, integration, E2E, and Windows release-smoke evidence
  is machine-generated rather than a hand-written test count;
- maintained docs match executable behavior and keep 2.1 durability, 2.2
  aggregation, and 2.3 retrieval convergence outside 2.0.
