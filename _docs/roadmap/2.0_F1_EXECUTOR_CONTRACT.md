## Scope

F1 introduces a Kernel-owned protocol v1 in
[`executors.py`](../../modules/kernel/executors.py): `ExecutorRuntime`,
`ExecutorCapabilities`, `ExecutorRequest`, `ExecutorResult`, `ExecutorEvent`,
and `ExecutorHealth`. `FakeExecutor` supplies deterministic outcomes at the
public execution seam. The request carries the existing project-owned
`AgentCommand`, so Task identity, finite budget, allowed tools, and permission
request retain their Slice 2 validation. The response carries `AgentResult`;
the Kernel still performs budget accounting, output validation, Task state
transition, checkpoint creation, and Run reduction.

`KernelExecutionEngine` now invokes the selected `ExecutorRuntime` after health,
protocol, and capability checks. It rejects an unavailable Executor, missing
capability, unsupported version, wrong response version/request ID, and
malformed response before recording success. A cancellation observed after an
Executor returns cannot be replaced by a reported success. The constructor's
existing `runtimes` argument remains compatible: a private
`LegacyAgentRuntimeAdapter` wraps existing `AgentRuntime` implementations,
including `DeterministicAgentRuntime`, and presents the same versioned path.

`ExecutorEvent` and ordered event lists are bounded typed result contracts.
F1 validates event type, request correlation, and contiguous sequence; it does
not yet stream events or persist Executor event details. F3 owns Bridge event
delivery and Run/Step/Event mapping.

## Deliberate limits

- No MyHarness import, checkout, process, model call, or production dependency.
- No Node/JSONL wire serialization, SDK Bridge, or source lock; those begin
  only after F2's exact-source read-only PoC.
- No Task-bound Workspace assignment, real write, Artifact registration,
  exact-action Approval consumption, or independent Executor tool permission.
- `ExecutorHealth` is a local contract. External liveness and process-tree
  cancellation are F2/F3 evidence, not claimed by FakeExecutor.
- A successful Executor result remains subject to current Slice 2 Kernel
  transitions. The later Reviewer/Tester and complete budget mapping remain
  separate phases under the [Fusion ADR](../adr/MYHARNESS_EXECUTOR_ADR.md).

## Verification

The new public-seam tests cover successful FakeExecutor execution while the
Coordinator retains Task ownership, handshake denial before side effects,
mismatched response rejection, event correlation/order, and cancellation
precedence. Existing Kernel execution tests protect legacy compatibility.
For the candidate branch, use Python 3.11 to run the Kernel tests, the complete
suite with unhandled thread warnings promoted to errors, strict Registry,
Model Gateway no-bypass, and `compileall`. Exact-head Windows Actions and a
clean runtime smoke remain required before merge.
